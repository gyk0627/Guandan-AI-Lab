# 云服务器租用方案（RENT PLAN）

> 依据：本仓库 E01/E16/E17/E18/E19 的实测数据。
> 结论先行：**先租一台便宜的验证机跑 2 天**，确认"多少核配一张卡"，
> 再决定长期租什么。不要一上来就租 96 核。

---

## 一、分两步租

| 阶段 | 目的 | 时长 | 配置 |
|---|---|---|---|
| **① 验证机** | 确认 CPU↔GPU 配比、跑通管线 | 1–2 天（按小时） | 1× 4090 24GB + **32 vCPU** + 64GB 内存 + 200GB 系统盘 + 500GB 数据盘 |
| **② 生产机** | 跑 1000 万局自我对弈 | 3–6 天 | 按①的实测结果调整；1× 4090 + 32–64 vCPU + 128GB + **1TB 数据盘** |

**关键**：①的结论决定②要不要加核。如果 32 进程时 GPU 已经吃满，加核纯属浪费。

---

## 二、各项怎么选（附实测依据）

### GPU：优先 4090 24GB，不必上 A100/H100

- 训练只占 **0.34 GB 显存**（E17）；24GB 足够支撑 **20–30 个并行推理进程**。
- E19 证明训练步只用到峰值算力 **1.55%**，瓶颈是 kernel launch。
  所以**当前阶段不需要高端卡**——A10 / L20 这类也能跑，先用便宜卡验证。
- 如果要跑更大的模型（放大 5–10 倍）再考虑 32GB+。

### CPU：32 vCPU 起步，别直接上 96

- 自我对弈是 **CPU 引擎**主导（E01：单核 5–10 局/秒随机、5 局/秒启发式）。
- 笔记本上 4–8 进程见顶（E16），但那是功耗墙；**服务器上未知**，
  这正是验证机要测的。
- 选型要点：**要物理核多的型号**（EPYC 7003/9004 系列），
  避开"超售 vCPU"的共享型实例——自我对弈是持续满核负载，超售会严重拖慢。

### 内存：64GB 够验证，128GB 够生产

- 每个自我对弈进程约 **0.8–1.5 GB**（torch + 模型）。
- 32 进程 ≈ 30–50 GB；64 进程 ≈ 50–100 GB。

### 磁盘：**数据盘必须 NVMe，且 ≥1TB**

实测单位（E02/E12/A17）：

| 目标 | JSONL | npz | 合计 |
|---|---:|---:|---:|
| 100 万局 | ~45 GB | ~20 GB | ~65 GB |
| 1000 万局 | ~450 GB | ~200 GB | **~650 GB** |
| 3000 万局 | ~1.3 TB | ~0.6 TB | ~1.9 TB |

- 导出是**写密集**（E01：440 样本/秒，单线程），机械盘或网络盘会成为瓶颈。
- 系统盘 100–200GB 足够（代码 + 环境 + 模型）。

### 镜像与系统：Ubuntu 22.04/24.04 + CUDA 12.x + PyTorch 2.x

- 直接选带 PyTorch 的官方镜像，省掉装环境。
- **注意**：仓库里的资源采样器原来是 Windows PowerShell 版，
  已补了跨平台版 `tools/resource_sampler.py`（Linux 读 `/proc`，零依赖），
  基准工具会自动调用，无需额外安装。

## 三、成本粗估（务必以平台实价为准）

| 项 | 估算 |
|---|---|
| 4090 按小时租赁 | 约 ¥2–6 / 小时（算力平台通常比大云便宜） |
| ① 验证机 2 天 | **约 ¥100–300** |
| ② 生产机跑 1000 万局 | 生成 70–140 小时（按 20–40 局/秒估）+ 导出，**约 ¥500–1500** |

> 相比"买错 64 核工作站"的代价（数万元），先花两三百块验证非常划算。

## 四、租到机器后的执行顺序（照抄即可）

```bash
# 0. 环境
git clone <repo> && cd GuanDan-AI-Lab
python -m venv .venv && . .venv/bin/activate
pip install torch numpy          # CUDA 版按平台指引

# 1. 机器基准（约 2 分钟）——记录 JSON，便于与笔记本对比
python -m tools.benchmark_suite

# 2. ★核心：CPU 扩展性（约 10 分钟）
python -m tools.scaling_test --configs 1,2,4,8,16,32 --games 60
# 看"局/秒"在哪一档拐平：
#   32 档仍在涨  -> CPU 不够，生产机考虑 64 核
#   16~24 拐平且 GPU 使用率高 -> 32 核足够，钱花在卡上

# 3. 训练侧确认（batch 放大 + launch 开销）
python -m tools.roofline_probe

# 4. 数据管线实测（生成→导出）
python -m tools.speed_test --games 500
```

**判断标准**（来自实测）：

- scaling 拐点 < 核数 → 再加核无用；
- `roofline_probe` 里步时随 batch 不变 → 仍是 launch 瓶颈，
  上线前先做 batch 512 / CUDA Graphs；
- `speed_test` 的导出速度若明显低于 440 样本/秒 → 数据盘或 CPU 有问题。

---

## 五、租用建议一句话总结

> **先租"1×4090 + 32 vCPU + 64GB + 1TB NVMe"跑两天（约两三百元），
> 用 `scaling_test` 找到拐点，再决定长期机器要不要上 64 核。
> 卡不用买贵的，先把 batch 和 CUDA Graphs 优化了，再来评估是否换卡。**
