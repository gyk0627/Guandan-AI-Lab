## 摘要

不完全信息、四人两队合作、长视野的对局中，蒙特卡洛回报的方差极大。深度蒙特卡洛（Deep Monte-Carlo, DMC）以整局硬回报回归动作价值，其隐含假设是「价值估计足够准，就能支撑决策」。本文以掼蛋为**基准环境**（而非棋力竞赛对象），给出一套可复现的规则引擎、数据管线与配对评估协议，并用受控实验检验上述假设。

我们发现该假设在弱监督、小算力的设定下不成立，且失效方式与直觉相反：行为克隆（BC）基线在当前 v3 表示上验证一致率 0.7500、对启发式老师胜率 53.00% [E11]（早期 v2 表示为 0.7562 / 48.50%）[E02]；价值网络在 v2 状态上的验证 AUC 为 0.635 [E04]，加入出牌历史后升到 0.6997 [E11]；但把该价值网络用于一步前瞻，对启发式老师的胜率从 BC 的 51.50% 降到 26.00% [E05]，换成 AUC 更高的 v3 价值网络后进一步降到 16.50% [E11]（两次前瞻实验使用同一套前瞻实现，差别只在价值网络与状态表示）。`top_k=1` 对照组（不真正覆盖动作）胜率 51.50%、逐局与基线一致，排除了实现缺陷 [E05]。

指标层面的诊断解释了这一现象：同一个价值网络（AUC 0.69967）在**同一局面内**把老师动作排第一的比例只有 28.81%（K=4，随机 20%；K=1 二选一为 55.14%，随机 50%），而同一测试下策略网络为 59.06% [E13]。也就是说，**全局 AUC 不是「价值能否用于决策」的充分指标**。

据此，本文提出 **Soft-DMC**：以软价值目标（软化/分布化回报、兄弟动作对监督、决策内偏好目标）降低目标方差，以软动作采样（温度 softmax 采样）替代 argmax，并把**决策内偏好准确率**纳入评价体系。软动作采样已实现 [X:2026-11-04]；软价值目标尚未实现，本文给出设计与已排除的失败路径——软标签（`0.5×胜负+0.5×升级数/3`）使验证 AUC 从 0.6997 降到 0.6954、决策内偏好从 28.81% 变到 29.18% [E15]。作为 RLHF 校准的先导实验，单负样本的成对偏好目标把对老师胜率从 53.00% 拉到 29.00%、对 BC 胜率只有 20.50% [E14]，说明「用奖励模型直接挑牌」不可行，RLHF 必须配合策略优化与 KL 约束。

系统侧，本文给出算力画像以说明为什么选择「改目标」而不是「堆采样」：CPU 规则引擎单核 5.2–10 局/秒 [E01]，4 进程并行自对弈加速 3.04×、1000 万局约需 3700 核时 [E08]；训练步的实测算力利用率仅 1.55%、带宽利用率 0.40% [E19]。所有结论限于当前设定（手工特征 v2/v3、5000 局老师数据、200 局配对评估、Wilson 区间），不外推为「掼蛋不可搜索」。

**关键词**：不完全信息博弈；深度蒙特卡洛；软目标；行为克隆；人类反馈强化学习；掼蛋；可复现性

## 1. 引言

### 1.1 研究问题

掼蛋是四人两队（对家结盟）的不完全信息牌类游戏：两副牌、万能牌（红桃级牌）、多级牌型阶梯、贡牌与升级机制 [docs/RULES.md](../RULES.md)。这些性质叠加后产生本文关心的三个难点：

1. **不完全信息**：决策时只能看到自己的手牌与公开出牌历史，其余三家的手牌与出牌顺序是隐藏的；
2. **团队合作**：效用是队伍的（头游归属与升级数），存在让牌、垫牌、牺牲等无法由单人心智模型解释的行为 [O:§1]；
3. **长局高方差**：一局包含上百个决策步，而回报（胜负/升级数）在一局结束时才确定，且高度依赖发牌与队友。

第 3 点直接指向 DMC 的方法论困难。DMC 用整局回报 `R` 作为动作价值目标 `Q(s,a) ≈ E[R | s,a]`，目标无偏、实现简单，但**方差极大**；而掼蛋中相邻候选动作的真实价值差往往很小（§7.5 实测为 0.01–0.05 量级 [E05]），一旦估计误差大于价值差，「用价值裁决动作」就等价于注入噪声。

### 1.2 为什么不是「再刷一次棋力」

同基准上已有强 RL 结果：DanZero 用 160 CPU + 1 GPU 训练 30 天达到人类水平 [W]；DanZero+ 进一步做到压制级表现 [W]；DouZero 以 DMC + 动作编码在斗地主上登顶 Botzone [W]。在单机、单卡、数千局数据的条件下重复这条路线既不可行，也不产生新知识。

本文因此把问题换成：**在硬回报目标下，价值网络要达到什么程度才能支撑搜索？如果达不到，失效的机制是什么，应当改目标还是改搜索？** 这一问题的答案不依赖棋力上限，而且对任何「长局 + 合作 + 不完全信息」的博弈都有迁移价值。

### 1.3 贡献

1. **可复现基准与度量**（§4、§10）：规则引擎与数据管线带 427 条测试 [X:2026-11-04]（`pytest tests -q`，实测 28.97 s）、300 局逐手重放零违规、发牌随机性检验 p=0.84 [O:§3]；配对对抗评估协议（同种子换边 + Wilson 置信区间）已工具化。
2. **失效分析**（§7）：一步前瞻在硬价值下把胜率从 51.50% 降到 26.00% [E05]，`top_k=1` 对照组逐局一致，排除实现缺陷；AUC 更高的 v3 价值网络使前瞻进一步降到 16.50% [E11]。
3. **指标批判**（§7.3）：证明全局 AUC 与「可用于决策」不等价，提出并实测**决策内偏好准确率**（28.81% vs 随机 20%，策略网络对照 59.06%）[E13]。
4. **方法路线**（§8、§9）：给出 Soft-DMC 的算法草案（软目标 + 软采样）与 RLHF 校准的数据协议；软动作采样已实现，软目标给出设计与已排除方案（软标签，E15）。
5. **诚实的负结果**（§12）：前瞻、成对奖励、软标签、正则化、状态表示五组负结果全部报告，并给出机制解释与「下一步不该做什么」的清单。

### 1.4 本文不主张什么

- 不主张掼蛋不可搜索，也不主张策略上限是 53.00%；负结果只在「BC 初始化 + 弱价值网络 + 单步前瞻」的受限设定下成立。
- 不主张 Soft-DMC 是唯一解，只主张它是当前负结果所指向的、可检验的下一步。
- 不与人类高手比棋力：本文的「老师」是启发式策略，BC 的天花板即老师本身（§6）。

## 2. 问题形式化

### 2.1 不完全信息扩展式博弈

记玩家集 `N = {0,1,2,3}`，队伍映射 `team(i) = i mod 2`（0、2 一队；1、3 一队）。一局是扩展式博弈 `(N, H, Z, A, P, I, u)`：`H` 为历史（含终止历史 `Z`），`A(h)` 为合法动作集，`P(h)` 为行动玩家，`I` 为信息集划分，`u = (u_0,…,u_3)` 为效用。掼蛋的效用是队伍级的：`u_i = f(头游归属, 升级数)`，同队两人共享（§2.3）。

与 POMDP 的对应：观测 = 自己的手牌 + 公开出牌历史 + 各家剩余张数 + 当前级牌；隐藏状态 = 其余三家的手牌与牌序。信息集 `I(h)` 收集所有「观测相同、隐藏状态不同」的历史。

### 2.2 回报的高方差

设单局回报 `R ∈ {0,1}`（本队是否头游）或 `R ∈ {0,1,2,3}`（升级数）。对决策点 `(s,a)`：

```
Q(s,a) = E[ R | s = s_t, a = a_t ],   Var(R | s,a) 由 (i) 发牌随机性 (ii) 队友/对手策略 (iii) 后续上百步的耦合共同决定
```

三个方差来源中，(i) 在决策时已经固定（手牌已知），(ii)(iii) 无法消除。硬 DMC 把单局 `R` 直接当回归目标，等价于用**一条采样**估计一个高方差随机变量；在 `|Q(s,a_1) - Q(s,a_2)|` 远小于 `sqrt(Var(R|s,a)/n)` 时，学到的排序由噪声主导。

这一分析给出两个可检验的推论：(a) 价值网络的**全局**排序指标（AUC）可以在噪声中做得不错，因为大部分样本对的价值差很大（例如「手里有炸弹 vs 没炸弹」）；(b) 但在**同一局面的相邻候选**之间（价值差 0.01–0.05），分辨力会崩溃。§7.4 的决策内偏好实验正是对 (b) 的直接检验。

### 2.3 基准环境规格（摘要）

掼蛋：两副牌共 108 张，四人各 27 张；对家结盟；级牌与红桃级牌（万能牌）参与牌型构造；牌型含单张、对子、三张、三带二、顺子、连对、飞机、炸弹（4 张及以上）、同花顺、四大天王；出牌需同牌型同张数且更大，炸弹可越级压制；一局以三家出完、剩余一家的名次结束，按队伍名次升级（头游 + 二游升 3 级，头游 + 三游升 2 级，头游 + 末游升 1 级）。规则实现的判定细节以规则引擎与 [RULES.md](../RULES.md) 为准，本文只把它当作基准环境规格使用，不展开为游戏介绍。

## 3. 相关工作

本节按四条脉络组织，文献底稿与 DOI 核对见 [W]（检索日期 2026-11-03）。

### 3.1 PIMC 与不完全信息搜索

确定化 + 完美信息搜索（PIMC）是牌类 AI 的经典路线：GIB 在桥牌上达到专家级 [1]；Long 等用合成博弈树识别决定 PIMC 强弱的博弈性质，解释了「理论有缺陷、实践常有效」[2]；Solinas 等用监督学习改善确定化的采样分布 [3]；Arjonilla 等针对 strategy fusion 提出推迟推理 [4]；ISMCTS 用信息集节点从结构上规避 strategy fusion 与 non-locality [5]。

**与本文的关系**：这些工作修补的是**信息集结构**。本文承认这些缺陷，但把失效定位在另一层——价值目标的噪声与评估指标的错位。因此本文不加深搜索、不做多步前瞻，而是先修价值目标与度量。

### 3.2 搜索-学习融合

AlphaGo/AlphaGo Zero/AlphaZero 证明「策略网络 + 价值网络 + 树搜索」的闭环可以在完美信息博弈上超越人类 [6][7][8]；MuZero 学习隐式模型并在其上规划 [9]；ReBeL 把 CFR 式搜索与深度 RL 结合，用学到的价值函数做子博弈求解 [10]；Student of Games 把搜索与学习统一到一个框架 [11]。

**与本文的关系**：这一支的共同前提是「搜索给出的目标足够可靠」。本文的负结果正是该前提在**合作型、弱价值**设定下不成立的反例：单步前瞻既无 rollouts 也无可靠价值，26.00% 的胜率不说明「搜索无用」，而说明「硬价值目标不足以支撑搜索」[E05]。

### 3.3 深度蒙特卡洛（DMC）与硬回报目标

DMC 指「深度网络 + 蒙特卡洛回报回归」的范式：DouZero 用动作编码 + 并行 actor + 整局回报在斗地主上登顶 Botzone [12]；DanZero 把该范式搬到掼蛋，160 CPU + 1 GPU 训练 30 天达到人类水平 [13]；DanZero+ 是其后继 [14]。

硬回报目标的方差问题在 RL 里有长期的技术线索：TD(λ) 给出偏差-方差权衡的语言 [15]；Retrace(λ) 给出低方差、可安全离策略的回报估计 [16]；n-step 回报与分布化价值（C51、Rainbow）是两条降低方差/建模不确定性的主流手段 [17][18]；软标签与 label smoothing 说明「软目标」能抑制过自信、改善校准 [19][20]。

**与本文的关系**：DouZero/DanZero 证明硬 DMC 在大算力下可行；本文问的是另一个问题——在 2v2 合作、候选价值差极小、算力受限时，硬目标会把搜索带偏多少。本文的「软」直接借用软目标/软标签的含义 [19][20]，但对象是**回报目标**而非分类标签。

> 我们未检索到以「Soft-DMC」命名的公开工作（检索词 4 组，见 [W]），故本文把它作为方法主张提出，其组件依据分散在上述文献中。

### 3.4 掼蛋与相邻基准

国内已有掼蛋深度 RL 工作 [21]；GuanZero 走蒙特卡洛 + 网络编码调控行为 [22]；Zou 等在掼蛋自对弈上报告「预测—优化鸿沟」：单条谱系可显著优于匹配基线，但 5 个预注册复现种子无一为正、10 种子合并区间含 0 [23]。相邻基准上，PerfectDou 用完美信息蒸馏绕开不完美信息下的价值估计 [24]；Suphx 用 oracle guiding 缓解麻将的价值估计难题 [25]。

**与本文的关系**：Zou 等是与本文最接近的负结果研究——「能预测结果」不等于「能提供可靠的优化方向」。本文从价值目标方差与「全局 AUC ≠ 决策可用」的角度给出互补解释，并提出软目标与 RLHF 校准作为应对。与 PerfectDou/Suphx 的差别在于：本文没有完美信息教师，也没有额外信息源，只能在弱监督下工作——这既是限制，也是本文负结果更「干净」的原因。

### 3.5 RLHF 与策略校准

RLHF 的标准流程是「人类成对偏好 → 奖励模型 → KL 约束下优化策略」：Christiano 等给出方法原型 [26]；Stiennon 等示范完整闭环 [27]；InstructGPT 证明偏好信号可在保持能力的同时改变行为 [28]；Ziegler 等引入对参考策略的 KL 惩罚 [29]；DPO 把 KL 约束下的奖励最大化解析为分类损失 [30]；HH-RLHF 与 Constitutional AI 扩展了偏好数据的来源 [31][32]；Guo 等讨论神经网络校准 [33]；Gao 等给出奖励模型过优化的 scaling law [34]；Kaufmann 等的综述提供术语框架 [35]。

**与本文的关系**：本文借用的是 RLHF 的**校准**含义——让强策略在胜率之外对齐人类对打法的偏好（可解释牌路、不抛弃队友、不确定时保守），并用 KL 约束与早停防止奖励过优化。差别在对象：这里校准的是**博弈动作**，偏好对象是同一局面下的两个候选打法，而不是文本。

### 3.6 本文与文献的差异（一句话）

不修补搜索结构（区别于 PIMC/ISMCTS 系），不堆采样规模（区别于 DanZero 系），不校准文本（区别于 RLHF 系）；本文做的是**价值目标层**的失效分析与度量重建。

## 4. 基准环境与可复现性

方法学论文的第一要求是「结论建立在可复现的基准上」。本节记录基准的审计证据。

### 4.1 规则引擎

- **测试**：当前实测 427 passed、28.97 s [X:2026-11-04]（早期历史时点值 349/359/370/423 见 [NUMBERS.md](NUMBERS.md) §I）。测试数增长主要来自状态编码 v3 的版本校验与数据合并的回归用例 [E11][E21]。
- **逐手重放**：300 局全量逐手重放，零违规 [O:§3]。重放会重算候选集合并与记录比对，任何不一致即报错。
- **比较关系**：牌型大小与炸弹压制关系的自动检查报告 0 矛盾 [O:§3]。
- **发牌随机性**：54 种「牌 → 座位」分布的卡方检验 p=0.84；成对牌（同点两张）的分布与独立模拟一致 [O:§3]。

### 4.2 数据管线

采集 → 结构校验 → 导出（逐局重放 + 候选重算 + 三重校验），失败即报错，不做静默跳过。导出侧的两项工程结论：

- **并行导出正确且有效**：300 局单进程 62.6 s → 4 分片 17.5 s（3.58×），10 个数组逐位相同；5000 局 478,895 样本单进程 1,335.1 s（22.3 min）→ 8 分片 215.4 s（3.6 min，6.20×），逐位一致 [E21]。
- **并行暴露过真实 bug**：`merge_datasets` 的局号偏移在分片合并时翻倍，已修复并补 2 条回归测试 [E21]。这条记录的意义是：并行化不是性能优化，而是**正确性检验手段**。

### 4.3 复现协议

所有对局评估使用同一协议：同一组种子下双方各打一半座位（换边），报告胜率与 Wilson 95% 置信区间；评估种子 300..399 [O:§12]。数据采集种子 40000..44999，自我对弈种子 70000+/500000+ [O:§12]。注意：`players.neural.register()` 与 `evaluate_neural` 在不显式传 checkpoint 时会按修改时间取最新模型，正式评估必须显式指定 [M]——这是复现性上最容易踩的坑，本文所有报告数字均对应显式 checkpoint。

## 5. 表示与策略网络

### 5.1 候选打分范式

掼蛋每一步的合法动作数随局面剧烈变化（同一手牌领出可有上千个候选，实测最大 1536 [E02]），固定输出维度的分类头不可用。本文采用**候选打分**结构 [M]：

```
state (198 / 258) ──► state_net ──► h (128)
candidate (65)     ──► cand_net  ──► c (128)
score = MLP([h, c])                 （逐候选打分，mask 掉非法候选置 -1e9）
value = MLP(h)                      （辅助头，预测本队是否头游）
```

网络规模刻意保持小：state tower 为 `Linear(state_dim, 256) → ReLU → Dropout(0.1) → Linear(256, 128) → ReLU`，candidate tower 为 `Linear(65,128) → ReLU → Linear(128,128) → ReLU`，打分头为 `Linear(256,128) → ReLU → Linear(128,1)` [X:2026-11-04，读 training/model.py]。

动作编码 65 维 = 牌面 54 + 牌型 9 + 张数 1 + 过牌 1；候选集 = 合法出牌 + 过牌（过牌排在最后）[O:§4]。

### 5.2 状态表示 v2 与 v3

| 版本 | 维度 | 组成 |
|---|---:|---|
| v2 | 198 | 手牌、已出牌池、各家剩余张数、级牌、pass_count、上一手 [O:§4] |
| v3 | 258 | 在 v2 上追加：最近 6 手序列（座位 24 + 特征 24）、双方进度 2、出完人数 2、炸弹数 2、手牌结构 6 [E11] |

v3 的动机是给价值估计补上「时间维度」：v2 是准静态快照，无法区分「刚被压过一手」与「连续让牌」这类时间相关信息。

### 5.3 信息约束

编码器只读自己的手牌与公开信息；有专门测试保证不读别家牌面 [O:§4]。v3 引入编码器版本校验，防止新旧特征错位——这是状态表示迭代中最容易静默出错的地方 [E11]。

## 6. 监督基线：行为克隆的天花板

### 6.1 设置

5000 局启发式老师对局、478,895 条决策样本；按局切分 430,847 训练 / 48,048 验证；平均候选 23.53、最大 1536；过牌占全部决策的 0.5759（过半决策是「过」）[E02]。训练目标为带 mask 的交叉熵（让老师动作的分数高于同批其它合法动作），40 轮、batch 64。

### 6.2 结果

- 验证一致率 **0.7562**，出现在第 37 轮；训练/验证 loss 0.8564 / 1.0143 [E02]。
- 旧 v2 模型对启发式老师：**48.50%**（400 局配对，Wilson CI 43.64–53.39），分边 49.0% / 48.0%（无先手偏差）；成对局面统计为全胜 50 / 一胜一负 94 / 全负 56 [E02][O:§5]。该模型在 200 局协议下复测为 51.50%（103/200，CI 44.61–58.33），与 48.50% 的差异属抽样波动（两 CI 重叠）[E05]。
- 当前 v3 模型（表示见 §5.2）：验证一致率 0.7500，对老师 **53.00%**（200 局 / 100 对，CI 46.09–59.80；`evaluation/policies_neural_vs_heuristic_20261103_205210.json` 记录 `games: 200`、`a_wins: 106`）[E11]。这是本文 BC 基线的**当前主口径**。
- 分桶一致率（验证集 27,725 条）：2 候选 0.990（5,383 条）、3–5 候选 0.815（5,949）、6–20 候选 0.697（8,530）、21–100 候选 0.560（5,263）、101+ 候选 0.429（2,600）[M]。候选越多越难，说明模型在大动作空间上的排序能力先于整体一致率崩溃。

**口径说明**：本文出现三个 BC 胜率数字，条件不同、**不可混用**：**v3 模型 200 局 53.00%**（当前主口径）[E11]；**v2 模型 400 局 48.50%**（E02 的原始评估）[E02]；**v2 模型 200 局复测 51.50%**（E05 前瞻实验的对照基线，与前瞻共用同一 v2 checkpoint 与同一种子协议）[E05]。三者置信区间相互重叠，差异不足以支持模型优劣结论；正文每一处都标明模型版本与局数。完整列表见 [NUMBERS.md](NUMBERS.md) §I。

### 6.3 结论

BC 的天花板就是老师本身：在纯监督设定下，模型无法超过产生数据的策略，只能逼近它。这既是转向 RL 的动机（需要回报信号才能超过老师），也是「人类数据/偏好不可替代」的论据——要突破启发式老师的上限，必须引入新的信息源（自对弈回报或人类偏好）。

## 7. 价值目标与搜索：硬 DMC 的失效（核心实证）

### 7.1 价值网络

标签为 `team_win`（本队是否头游），与策略网络解耦的独立 `ValueNet`：`Linear(state_dim,256) → ReLU → Dropout(0.1) → Linear(256,128) → ReLU → Linear(128,1)` [X:2026-11-04，读 training/model.py]。

| 设置 | 验证 AUC | 备注 |
|---|---:|---|
| v2 状态，478,895 样本 | **0.6351**（第 3 轮） | 第 4 轮起过拟合：验证 loss 0.72 → 1.31、训练 AUC 升至 0.966（第 20 轮）[E04] |
| v3 状态，同规模数据 | **0.6997** | 单项最大提升（+0.065）[E11] |
| 合并 6000 局（老师 5000 + 克隆自对弈 1000，580,805 样本） | 0.6426（第 5 轮） | 仅 +0.008 [E10] |
| 克隆策略自对弈 1000 局重训（101,910 样本） | 0.5558（第 1 轮） | 假设被否定，但非受控（10 万 vs 48 万样本）[E06] |

数据量缩放（E07）：300 局 / 28,789 样本 → AUC 0.5491；1000 局 / 95,748 → 0.5234（噪声点）；2000 局 / 191,608 → 0.6197；5000 局 / 478,895 → 0.6351 [E07]。结论：AUC 随数据量上升，但边际收益很低；按端到端单核吞吐推算，1000 万局约需 964 单核小时，本机不现实 [E01][E07]。

正则化扫描（E09，全负）：基线（hidden 256、无正则）0.6351；weight decay 1e-2 → 0.5347（第 16 轮）；dropout 0.3 + wd 1e-2 + hidden 128 → 0.5357（第 1 轮）；dropout 0.5 + wd 5e-2 + hidden 64 → 0.5000（模型塌缩为常数）[E09]。结论：**早停 + 不加正则**是当前数据规模下最稳的配置。

### 7.2 硬价值 + 一步前瞻 = 显著变差

一步前瞻（lookahead）的规则：策略网络取 top-k 候选（`k=3/5`），对每个候选执行之、用价值网络评估后继局面的本队胜率，选价值最高者；可加「价值差门槛」（候选间价值差小于 `gap` 时退回 BC）；候选数超过 60 时直接退回 BC（编码 500 个候选约需 200 ms，单步开销不可接受）[E05]。

| 策略（200 局配对，种子 300..399 换边） | 胜率 | Wilson 95% CI | 前瞻触发率 |
|---|---:|---|---:|
| BC 基线（v2 状态） | 51.50%（103/200） | 44.61–58.33 | — |
| 对照：`top_k=1`（不真正覆盖） | 51.50%（103/200） | 同上，**逐局与基线相同** | 86.7% |
| 前瞻 `top_k=3` | 34.50%（69/200） | 28.26–41.32 | 89.5% |
| 前瞻 `top_k=5` | **26.00%**（52/200） | 20.41–32.49 | 87.9% |
| 前瞻 `top_k=5` + 价值差门槛 0.15 | 42.00%（84/200） | 35.37–48.93 | 87.9% |
| 前瞻 `top_k=5` vs BC 直接对打 | 24.50%（49/200） | 19.06–30.90 | 90.8% |
| 前瞻 `top_k=5`（E10 价值网络，AUC 0.6426） | 31.50%（63/200） | 25.46–38.24 | 90.4% |

（以上均见 [E05]，价值网络来源见 [E10]；`top_k=1` 的逐局一致是排除实现缺陷的关键对照。）

### 7.3 更强的价值网络让搜索更糟

| 指标 | v2 状态 | v3 状态 |
|---|---:|---:|
| 价值 AUC | 0.6351 [E04] | **0.6997** [E11] |
| BC 对启发式 | 51.50%（v2，200 局复测；400 局为 48.50%）[E05][E02] | 53.00%（v3，200 局，CI 46.09–59.80）[E11] |
| 一步前瞻（top5）对启发式 | 26.00% [E05] | **16.50%**（CI 12.00–22.27）[E11] |
| 前瞻（top3 + 价值差门槛 0.1） | — | 39.50%（CI 32.98–46.41）[E11] |

AUC 提升 0.065，前瞻胜率下降 9.5 pp [本文计算：26.00 − 16.50]。这不是「训练不够」，而是**指标与用途错位**。

### 7.4 决策内偏好：指标层面的诊断

构造「同一局面内」的候选集合并检验价值网络的排序能力：对 40 局、1590 次采样决策，随机取 K 个候选（含老师动作），看价值网络是否把老师动作排第一 [E13]。

| 指标 | 数值 | 随机基线 |
|---|---:|---:|
| 价值网络（AUC 0.69967）K=4 排第一 | **28.81%**（458/1590，CI 26.63–31.08） | 20% |
| 价值网络 K=1 二选一 | 55.14%（869/1576，CI 52.67–57.58） | 50% |
| **策略网络** K=4 排第一（对照） | **59.06%**（939/1590） | 20% |

同一测试下策略网络 59.06%，证明工具与流程没有问题；价值网络的 28.81% 说明它**几乎没有决策内分辨力**。同时测得老师动作的平均价值优势（avg_margin）只有 0.0190 [E13]——即真实价值差本身就在噪声量级。

### 7.5 机制解释

1. **指标错位（已实测）**：全局 AUC 0.700 的值网络在决策内只有 28.81%，二选一 55.14% [E13]。AUC 由大量「价值差很大」的跨局面样本对主导，而决策只需要「同一局面内相邻候选」的排序。
2. **分布外自信错误**：价值网络在老师分布上训练，前瞻把状态推到分布外（老师不会走的分支）；网络越拟合训练分布，分布外错误越「硬」。这解释了为什么 AUC 0.635 时前瞻 26.00%、AUC 0.700 时反而 16.50% [E05][E11]。
3. **硬目标放大噪声**：稀疏高方差回报让价值网络在接近的候选间缺乏分辨力（avg_margin 0.0190 [E13]），于是「用价值裁决」等于把噪声注入策略——这正是需要软价值目标的位置。

## 8. 方法一：Soft-DMC（软深度蒙特卡洛）

### 8.1 定义

Soft-DMC = ①**软价值目标** + ②**软动作采样**；③RLHF 策略校准是可选的上层。

| 维度 | 硬 DMC（DouZero 系） | Soft-DMC（本文主张） |
|---|---|---|
| 价值目标 | 单局硬回报 `Q(s,a)` | 软化的期望回报 / 分布化回报 / 兄弟对比较目标 |
| 动作选择 | argmax 或 ε-greedy | 温度 softmax 采样（已实现） |
| 不确定性 | 不建模 | 分布头或温度显式建模 |
| 搜索用法 | 通常不用搜索 | 仅在**决策内偏好**可靠时启用前瞻 |

核心论点：**先把「价值能否分辨同一局面内的候选」做对，再谈搜索**。否则搜索只会放大噪声（§7）。

### 8.2 已实现部分：软动作采样

`players/sampling.py` 提供 `SamplingPolicy(base, temperature=1.0, epsilon=0.0, seed=None, name=None)` [X:2026-11-04]：以概率 `epsilon` 均匀随机，否则按 `softmax(scores / temperature)` 采样（`torch.multinomial`）；`temperature <= 0` 退化为 argmax。注释明确把它对应到 SDMC 的 soft action sampling。

其意义不在于「更好」——在纯评估中温度采样通常略低于 argmax——而在于它让策略分布成为**可调对象**：温度与 ε 构成探索-利用的连续旋钮，也是后续 RLHF 校准的接口（校准改变的是分布，不是单个 argmax 动作）。

### 8.3 待实现部分：软价值目标

**已排除的路径（E15，负结果）**：把标签换成 `0.5×胜负 + 0.5×升级数/3` 的软标签。结果：验证 AUC 0.6954（硬标签 0.6997）、决策内偏好 29.18%（硬标签 28.81%，CI 27.00–31.46）、老师动作价值优势 +0.0157（硬标签 +0.0190）[E15]。**只改标签形状无效**，缺口不在标签的软硬，而在缺少**兄弟动作之间的比较信号**。

**推荐设计（待实现）**：

1. **兄弟对监督（sibling supervision）**：对同一决策点的不同候选各模拟一步得到相邻状态，用「哪一步之后更好」构造训练对，直接训练相邻状态比较，而不是整局回报回归。这是 E15 的直接推论：比较信号必须来自同一局面内的兄弟候选，而不是把全局标签变软。
2. **分布化价值**：预测 `p(R | s,a)`（分类头/分位数），用分布之间的 soft 比较替代点估计；可在「候选价值差小于估计误差」时显式给出不确定性 [17][18]。
3. **决策内偏好目标**：用成对比较（选中动作 vs 其它候选）构造目标，直接优化「同一局面下选对的概率」，与 §7.4 的评估指标同构。
4. **软采样作为策略侧的一半**：训练时用温度采样产生多样的后继，缓解「只走老师路径」的分布窄化。

预期收益：降低价值目标方差 → 提高候选间分辨力（决策内偏好）→ 前瞻不再注入噪声。**注意这是设计主张，不是已验证结论**；验证需要实现后按 §8.4 协议与 BC、硬 DMC 三方对照。

### 8.4 评价协议

1. **配对对抗**：同种子换边 + Wilson CI（`tools/eval_policies.py`，已实现）；
2. **决策内偏好准确率**：老师动作 vs 随机/次优动作的排序正确率（`tools/decision_preference.py`，已实现）；
3. **三方对照**：BC 基线 / 硬 DMC / Soft-DMC，同一评估种子与局数；
4. **报告门槛**：胜率差在 CI 之外、且决策内偏好同步提升，才认为软目标有效；仅 AUC 提升不算（§7 已证明 AUC 与可用性脱钩）。

## 9. 方法二：RLHF 策略校准（未来工作）

> 状态：**本期不实现**（负责人 2026-11-03 决定 [O:§8]）。本节保留为论文的「未来工作」与数据协议设计，**不作为本文已完成的贡献**；§9.4 的先导实验 E14 是已完成的反面证据。

### 9.1 问题：强策略 ≠ 符合人类偏好

自对弈/回报驱动的策略追求胜率，但人类偏好还包括可解释的牌路、不抛弃队友、不确定时保守、不机械重复等。这些偏好无法写进胜负效用，只能由人类反馈提供。

### 9.2 协议（拟）

1. **偏好数据采集**：同一局面给出两个候选打法（来自不同策略/温度），人类选更认可的一个。现有 `interface/web_server.py` 已把真人对局记录成 `replay/human_*.jsonl`，可扩展为「对比投票」界面 [O:§8]。
2. **奖励模型**：由 `(s, a_pref, a_rej)` 训练，输出可解释的偏好分数，并按 [33] 做概率校准检查。
3. **策略校准**：在 DMC/Soft-DMC 的策略更新中加入奖励项与 KL 约束（PPO 式载体 [36]），保持棋力；早停与 KL 系数按 [34] 的过优化规律设定。
4. **校准度量**：偏好一致率、与人类选择的 KL、**胜率保持度**（校准不应显著降低棋力）、以及 §7.4 的决策内偏好。

### 9.3 预期与风险

- 预期：在保持胜率的前提下提升偏好一致率；
- 风险：人类偏好数据噪声与规模不足；奖励模型过优化（需要 KL 与早停）[34]；
- 设计约束（来自 §9.4）：**奖励模型不得替代策略网络做动作选择**。

### 9.4 先导实验：成对奖励不能直接当挑牌器（E14，负结果）

在采人类数据之前，先用启发式老师冒充人类做「困难负样本」（同牌型同张数）的成对偏好训练。训练目标为成对比较（选中动作 vs 单负样本）；评估时直接用奖励模型对候选 argmax。

| 指标 | 行为克隆（softmax 全候选） | 成对比较（单负样本） |
|---|---:|---:|
| 决策内排第一（48,048 条验证集） | **0.8200** | 0.7462 |
| 对启发式老师胜率（200 局） | **53.00%** | 29.00%（CI 23.15–35.64） |
| 对行为克隆胜率（200 局） | — | 20.50%（CI 15.49–26.63） |

成对训练自身的二分类准确率为 0.904 [E14]，即「模型能区分训练对」，但把该分数用于全候选排序时崩溃。

**结论**：单负样本的成对目标学到的是「局部相对偏好」，不是「全局候选排序」；直接把奖励模型当挑牌器会显著变弱。这从反面确定 RLHF 的正确用法：①奖励模型只负责给轨迹/动作打偏好分；②必须配合策略优化（PPO 类）与 KL 约束；③评价要同时看胜率保持度与偏好一致率。

（工程教训：该实验早期因评估函数 `states` / `cand_offsets` 索引错位得到过 0.18 的荒谬胜率；错位修复后才有上表数字 [E14]。这类静默错位是「负结果不可信」的常见来源，故本文保留记录。）

## 10. 实验设置

### 10.1 硬件与软件

### 10.2 评估协议

- 价值网络：按局切分训练/验证（避免同局样本泄漏），报告验证 AUC 与最佳轮次。
- 决策内偏好：40 局、1590 次采样决策，K=4 与 K=1 两种设定，报告均值与 CI [E13]。
- 统计判定：吞吐类比较用 ±10% 判定「持平/更快/更慢」[E22]；胜率类比较看 CI 是否重叠。

## 11. 结果

### 11.1 规则与基线

见 §4（审计）与 §6（BC）：当前 v3 模型验证一致率 0.7500、对老师 **53.00%**（200 局 / 100 对，CI 46.09–59.80）[E11]；旧 v2 模型验证一致率 0.7562 [E02]、对老师 **48.50%**（400 局，CI 43.64–53.39），200 局复测 51.50% [E02][E05]，分边 49.0% / 48.0%（百分比口径，无先手偏差）[O:§5]。模型对随机策略胜率 93.00%（400 局，CI 90.07–95.11，分边 92.5/93.5）[R]，而启发式对随机为 88.00% [R]——即 BC 只是略微超过老师对随机的水平，并未获得超出老师的棋力。

### 11.2 价值估计

见 §7.1：v2 0.6351 [E04]、v3 0.6997 [E11]、合并 6000 局 0.6426 [E10]、克隆数据重训 0.5558 [E06]、缩放 0.5491→0.6351 [E07]、正则化全负 [E09]。

### 11.4 系统与算力

**吞吐（E01）**：CPU 随机策略 10.0 局/秒/核（1,232 决策/秒）、启发式 5.2 局/秒（511 决策/秒）、端到端 2.88 局/秒（325 ms/局）；GPU 推理 batch=1 为 2,628 决策/秒、batch=64 为 156,937 决策/秒 [E01]。单核 1000 万局约 964 h（随机策略 278 h、启发式 531 h）——瓶颈在 CPU 规则引擎，不在 GPU [E01]。

**并行（E08/E16）**：自对弈 4 进程从 3.02 局/秒升到 9.17 局/秒，加速 3.04×（效率 76%）；折算 0.75 局/秒/核，1000 万局约 3700 核时（32 核约 115 h，64 核约 58 h）[E08]。CPU 扩展性测试峰值加速 2.05×（全神经网，4–8 进程）与 2.32×（纯 CPU）[E16]；限制单线程后 4→4.60、8→4.60、12→4.04、16→2.42 局/秒，说明瓶颈是平台功耗/散热与超线程，而非 GPU [E16]。

**基准（E17 vs E22）**：

**算力上限（E19）**：矩阵乘实测 9.49 TFLOPS、带宽 284.6 GB/s、脊点 33.3 FLOP/Byte；训练步（batch=64）耗时 1.93 ms、实际算力 0.148 TFLOPS（利用率 1.55%）、带宽 1.17 GB/s（0.40%）、算术强度 126.5 [E19]。batch 64→512 时步时基本不变（2.12→2.03 ms），样本吞吐 30,216→251,780 样本/秒；batch=1024 步时反而升到 2.92 ms [E19]。结论：瓶颈是 kernel launch 的固定开销，换更强 GPU 的收益有限——这支持「把预算投在目标设计而非硬件」。

**真实数据 batch 消融（E20）**：311,662 训练 / 34,591 验证样本、3 轮；固定 lr 1e-3 时 batch 64→512 的样本吞吐从 13,592 升到 40,412（2.97×），但验证准确率从 0.6226 降到 0.6061；线性缩放 lr 未补回精度（0.6047）[E20]。真实吞吐 2.97× 远低于合成基准的 8.3×，组批的 Amdahl 上限约 44% [E20][E19]。长程训练用 batch=512 可省约 70% 墙钟 [E20]。

**数据加载（E18）**：后台预取 0/1/2/4 线程对应 279.0/300.8/306.5/302.3 步/秒，2 线程仅 +9.9%，等待数据只占 7% [E18]。把 CPU 核让给训练没有意义。

**导出（E21）**：见 §4.2，5000 局导出 6.20×，逐位一致。

## 12. 负结果与失效分析

本文的五组负结果是方法主张的直接依据，全部保留。

### 12.1 负结果清单

| # | 尝试 | 结果 | 判据 |
|---|---|---|---|
| N1 | 硬价值 + 一步前瞻（top3/top5） | 51.50% → 34.50% / **26.00%** | 200 局配对，`top_k=1` 对照 51.50% 逐局一致 [E05] |
| N2 | 更强的价值（v3，AUC 0.6997）+ 前瞻 | → **16.50%** | AUC ↑0.065、胜率 ↓9.5 pp [E11][本文计算] |
| N3 | 成对奖励直接挑牌（单负样本） | 对老师 **29.00%**、对 BC 20.50% | 决策内排第一 0.7462 < BC 0.8200 [E14] |
| N4 | 软标签（0.5×胜负 + 0.5×升级数/3） | AUC 0.6954、决策内 **29.18%** | 均未超过硬标签 0.6997 / 28.81% [E15] |
| N5 | 正则化（wd / dropout / 缩容） | 0.5347 / 0.5357 / 0.5000 | 均低于基线 0.6351，最后一次塌缩为常数 [E09] |

另有两条次级负结果：克隆策略自对弈数据重训价值网络 AUC 0.5558（低于 0.635，但非受控）[E06]；6000 局混合数据只带来 +0.008 AUC [E10]。

### 12.2 为什么「更准的价值」救不了搜索

三条证据指向同一个结论：**问题在目标与指标，不在训练量**。

1. 数据量缩放曲线在 5000 局处仍在上升但边际收益很低，1000 万局约需 964 单核小时 [E07][E01]；继续堆数据的性价比极低。
2. 正则化全部为负 [E09]，说明过拟合不是主要矛盾（早停即可）。
3. 最关键：AUC 从 0.635 升到 0.700，前瞻胜率从 26.00% 掉到 16.50% [E05][E11]。若失效原因是「价值不准」，提高 AUC 应当改善前瞻；实际相反，说明**全局 AUC 度量的东西与搜索需要的东西不是同一个**。

### 12.3 教训

- **先建指标，再建方法**：若一开始就用决策内偏好（28.81%）而不是全局 AUC 作为判据，E11 的「AUC 提升」会被立刻识别为方向错误。
- **负结果需要对照组**：`top_k=1` 逐局一致 [E05] 是整个前瞻结论可信的前提；没有它，26.00% 可被解释为实现 bug。
- **软标签不是软目标**：把标签形状变软（E15）与提供兄弟动作比较信号是两件事，前者已证明无效。
- **奖励模型不能替代策略**：单体成对目标学不到全局排序（E14），RLHF 必须通过策略优化落地。
- **静默索引错误会伪造负结果**：E14 早期的 0.18 胜率来自 `states`/`cand_offsets` 错位 [E14]；评估管线需要「荒谬值报警」。

## 13. 局限

1. **软价值目标未实现**：本文只给出设计与已排除路径（E15），Soft-DMC 的完整实证尚未完成；软动作采样已实现但未做系统的温度扫描。
2. **RLHF 整体推迟**：人类偏好数据尚未采集，§9 是协议设计；E14 只提供了「不能怎么用」的反面证据。
3. **状态表示为手工特征**：v3 含最近 6 手历史，但仍非序列模型；更强的表示（Transformer/RNN over history）未测试。
4. **前瞻只做 1 步**，且未做队友联合决策（掼蛋的合作性要求联合动作空间，本文未涉及）。
5. **统计功效有限**：胜率评估以 200 局为主，CI 半宽约 6.9 pp [E05][本文计算]；AUC 差异 0.065 属中等效应，重尾方差不排除；价值网络的多次扫描未做多种子重复（E09/E07 均为单种子）。
6. **单机单卡**：所有系统结论限于 RTX 5060 Laptop + 18 核；1000 万局级实验未执行。
7. **老师即上限**：BC 天花板是启发式老师，因此「53.00%」不代表掼蛋策略上限；与 DanZero/DanZero+ 的棋力差距未量化。
8. **文档口径漂移**：仓库内 README、EXPERIMENTS、models/README 对同一指标存在不同数值（例如 BC 对老师 48.50% [E02] / 51.50% [E05] / 53.00% [E11][R]，AUC 0.6351/0.6997 [E04][E11]；历史测试数等其余口径差异见 [NUMBERS.md](NUMBERS.md) §I）。本文以 EXPERIMENTS 的实验编号为准并逐条标注条件，但这类漂移本身是复现性风险。

## 14. 结论

本文以掼蛋为基准环境，检验了「价值估计足够准就能支撑决策」这一 DMC 的隐含假设，并给出否定答案：价值网络全局 AUC 从 0.635 提到 0.700，一步前瞻的胜率却从 26.00% 掉到 16.50% [E05][E11]；`top_k=1` 对照组逐局与基线一致，排除了实现缺陷 [E05]。诊断指向指标错位——同一价值网络在决策内把老师动作排第一的比例只有 28.81%（策略网络对照 59.06%）[E13]——以及硬回报目标在相邻候选间缺乏分辨力（平均价值优势 0.0190）[E13]。

据此提出 Soft-DMC：以兄弟对监督/分布化价值/决策内偏好目标软化价值目标，以温度 softmax 采样软化动作选择，并把决策内偏好准确率纳入评价体系。软动作采样已实现，软目标给出了设计与已排除方案（软标签无效，E15）。RLHF 校准作为未来工作，其先导实验（E14）证明单负样本成对目标不能直接当挑牌器，校准必须配合策略优化与 KL 约束。

本文的贡献不是更高的棋力，而是一组可复现的负结果、一套可迁移的度量（配对换边 + Wilson CI + 决策内偏好）与一条明确可检验的下一步路线。我们相信，在长局、合作、不完全信息的博弈里，「把目标软化、把指标对准决策」比「把搜索加深、把算力堆大」更可能是正确的第一性问题。
