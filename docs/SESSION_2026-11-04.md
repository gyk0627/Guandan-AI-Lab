## 三、两次重要的结论修正（都写进 EXPERIMENTS 了）

1. **"GPU 只用了 39%"是错的**：`nvidia-smi utilization.gpu` 在 Windows/WDDM 上会低估。
   用任务管理器同源的 GPU Engine 计数器实测，训练时 3D 引擎 **87%–97%**。
2. **"GPU 算力吃满"也不准确**：Roofline 显示实际算力只到峰值 1.55%。
   引擎"忙"是在处理大量很小的 kernel，不等于在做数学运算。
   **真正瓶颈 = 每步固定开销（kernel launch）**。

## 四、由此得到的硬件结论

| 项 | 结论 |
|---|---|
| 显存 | 训练实际只占 **0.34 GB** → 24GB 充足，不必 48GB |
| 单卡算力 | 当前模型规模下收益有限；**先做 batch 512 / CUDA Graphs** |
| CPU 核 | 训练只需 1 核；**自我对弈才是 CPU 大户** |
| 数据盘 | 1000 万局 ≈ 650GB → **4TB 更稳**（2TB 够 1000 万） |
| 头号风险 | 高核数下"CPU 引擎 ↔ 单卡推理"的配比未知 → **必须先租机实测** |

详细方案：[HARDWARE.md](HARDWARE.md)（配置评估）、[RENT_PLAN.md](RENT_PLAN.md)（租什么、怎么测）。
